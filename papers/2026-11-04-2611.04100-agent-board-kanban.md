# The Agent Board: Kanban for Machines; Durable Coordination for Agents That Outlive the Conversation

- **Título:** The Agent Board: Kanban for Machines; Durable Coordination for Agents That Outlive the Conversation
- **Autores:** Tyler Hunt, Donald Nguyen, Gurbinder Gill
- **Data de submissão:** 3 nov 2026 (00:21 UTC; 2 nov, 21:21 horário de Brasília)
- **Link:** https://arxiv.org/abs/2611.04100
- **Tema:** Agentes / Multi-agente / Arquitetura

## Resumo

Os harnesses de LLM atuais seguem um formato de thread única: um agente, um histórico, uma máquina, uma sessão. Isso quebra quando o trabalho envolve vários agentes, dura mais que uma chamada ao modelo ou depende de sistemas que não são agentes. Os autores descrevem o Agent Board, a camada de coordenação do harness Corvic: uma tabela durável e compartilhada de tarefas "semi-semânticas", com alguns campos exatos para roteamento e um corpo livre em texto que só LLMs leem.

Agentes publicam, observam e bloqueiam em tarefas, encerrando o turno sem manter processo até serem acordados. Um agente de sistema, o Board Keeper, funciona como tratador de interrupções: traz eventos externos para o quadro, casa-os com tarefas em espera lendo o texto e aloca novos agentes quando a tarefa pede um tipo de agente. Políticas de coordenação carregáveis dão significado a status e papéis.

## Principais achados / contribuições

- Modelo de coordenação inspirado no kanban humano e comparado a um escalonador de sistema operacional para agentes (com discussão de onde a analogia falha).
- Separa o que o mecanismo garante do que fica por convenção.
- Nos pilotos simulados, o custo de espera do board ficou constante com o tempo de espera, enquanto polling ingênuo cresceu ~165x.
- Porém um watcher externo simples foi mais barato que o board.
- O Board Keeper não teve falsos despertares, mas perdeu 3,6% dos despertares reais.

## Possíveis aplicabilidades práticas

- Desenho de fluxos com vários agentes (ex.: agente de triagem de bugs, agente de code review, agente de release) que precisam esperar CI, aprovação humana ou outros sistemas.
- Substituir polling por espera orientada a eventos em automações com LLM, reduzindo custo.
- Usar campos estruturados para roteamento e texto livre só para o que o LLM precisa interpretar.
- Inspiração para integrar agentes de fornecedores diferentes via um quadro de tarefas comum.

## Minha opinião / insight

A ideia é simples e boa: tratar coordenação de agentes como um quadro de tarefas persistente, algo que times de engenharia já entendem. Mas a evidência é fraca — um trace de um board real e três pilotos pequenos simulados — e os próprios autores mostram que um watcher externo simples sai mais barato. Os 3,6% de despertares perdidos são um risco real em produção (tarefa parada sem ninguém perceber). Vale como blueprint arquitetural, não como prova de superioridade; eu começaria com fila/eventos tradicionais e usaria matching por LLM só onde os campos exatos não bastam.
